# AP3216C 模块说明

## 1. 模块定位

AP3216C 是当前项目中的 I2C 传感器模块，用来读取：

- IR
- ALS
- PS

它是这个仓库里比较典型的一条“从设备树到 Qt 页面”的完整链路示例。

---

## 2. 硬件与设备树

### 总线
- I2C：`i2c1`

### 设备树节点
位于 `dts/imx-emmc.dts` 的 `&i2c1` 下，核心信息为：

- `clock-frequency = <100000>`
- `compatible = "lsz,ap3216c"`
- `reg = <0x1e>`

这表示：
- AP3216C 挂在 `i2c1`
- 地址为 `0x1e`
- 驱动通过 compatible 进行匹配

---

## 3. 驱动层

### 路径
- `drivers/ap3216c/`

### 用户态接口
驱动导出：
- `/dev/ap3216c`

### 说明
AP3216C 这条链路的重点不是界面本身，而是：
- DTS 节点被识别
- 驱动匹配成功
- `/dev/ap3216c` 出现
- 用户态能读到三路数据

---

## 4. CLI 层

CLI 程序的作用是：
- 在没有 Qt 的情况下先验证 `/dev/ap3216c`
- 确认 `IR / ALS / PS` 数据链路正常

这一步很重要，因为它可以把问题先隔离在驱动层，而不是直接把 Qt 当成调试入口。

---

## 5. Qt 设备封装层

### 路径
- `apps/qt_app/LSZ_Terminal/device/ap3216cdevice.*`

### 当前做法
`Ap3216cDevice::readData(...)` 从设备节点读出 3 个 `unsigned short`，并填入：

- `ir`
- `als`
- `ps`

也就是说，Qt 页面看到的已经不是底层寄存器字节，而是驱动/设备类整理后的三路通道值。

---

## 6. Qt 采集线程层

### 路径
- `apps/qt_app/LSZ_Terminal/workers/ap3216cworker.*`

### 结构
- `Ap3216cWorker` 属于 `QObject`
- 被移动到单独 `QThread`
- 内部 `QTimer` 周期触发 `onTimeout()`
- 成功读取后 `emit dataReady(const Ap3216cData &data)`

这种方式把：
- 设备读取
- UI 刷新

分离开来，页面只负责显示，不直接频繁读设备。

---

## 7. Qt 页面层

### 路径
- `apps/qt_app/LSZ_Terminal/pages/sensorpage.*`

### 页面行为
`SensorPage` 中：
- 可设置采样周期
- 点击 Start 启动 AP3216C Worker
- 点击 Stop 停止 Worker
- 收到 `dataReady(...)` 后更新：
  - `IR`
  - `ALS`
  - `PS`

---

## 8. 当前链路总结

AP3216C 的完整链路可以概括为：

1. `dts/imx-emmc.dts` 描述 `ap3216c@1e`
2. 驱动匹配并导出 `/dev/ap3216c`
3. CLI 验证字符设备读链路
4. Qt `Ap3216cDevice` 封装 `/dev/ap3216c`
5. Qt `Ap3216cWorker` 周期采集
6. `SensorPage` 显示结果

这条链路非常适合后续作为“一个标准模块模板”去复制到其他 I2C 传感器上。
