# AP3216C 与 ICM20608 模块说明

## 1. 文档目的

本文档用于整理 `device_manager` 项目中 **AP3216C** 与 **ICM20608** 两个传感器模块的实现思路、目录位置、底层链路、用户态测试方式以及 Qt 集成方式，便于后续维护、汇报与扩展。

当前项目中，这两个模块已经打通了“**设备树 / 驱动 / 设备节点 / CLI 或 Qt**”这一基本链路，Qt 侧也已经可以完成手动读取与显示。

## 3. 总体架构

这两个模块在系统中的工作链路可以统一概括为：

```text
硬件传感器
   ↓
设备树节点（DTS）
   ↓
Linux 驱动（I2C 或 SPI）
   ↓
misc 字符设备节点（/dev/...）
   ↓
CLI 测试程序 / Qt 设备封装类
   ↓
Qt 页面显示
```

这套链路的意义是：

1. **设备树** 负责告诉内核“硬件在哪、接口怎么接”。
2. **驱动** 负责与寄存器通信，并将数据整理成用户态可用的形式。
3. **字符设备节点** 负责为用户态提供统一入口。
4. **CLI** 用于最小化验证，帮助快速判断问题出在驱动层还是应用层。
5. **Qt** 负责在最终界面中展示数据并提供操作入口。

# 4. AP3216C 模块说明

## 4.1 模块简介

AP3216C 是一颗光学类传感器，提供三类数据：

- **IR**：红外数据
- **ALS**：环境光数据
- **PS**：接近传感数据

在本项目中，AP3216C 通过 **I2C1** 接入 i.MX6ULL。

---

## 4.2 硬件连接与设备树

### 设备树节点

当前设备树中 AP3216C 节点位于 `&i2c1` 下，典型写法如下：

```dts
&i2c1 {
    clock-frequency = <100000>;
    pinctrl-names = "default";
    pinctrl-0 = <&pinctrl_i2c1>;
    status = "okay";

    ap3216c@1e {
        compatible = "alientek,ap3216c";
        reg = <0x1e>;
    };
};
```

### 含义说明

- `&i2c1`：表示 AP3216C 挂在 I2C1 控制器上。
- `clock-frequency = <100000>`：总线工作频率为 100 kHz。
- `reg = <0x1e>`：AP3216C 的 7 位从地址为 `0x1e`。
- `status = "okay"`：启用该 I2C 控制器及其子节点。
- `compatible`：用于驱动匹配。

### 注意事项

当前仓库中存在一个需要统一的点：

- DTS 中写的是：`"alientek,ap3216c"`
- 驱动 `of_match_table` 中写的是：`"lsz,ap3216c"`

这两者原则上应保持一致，否则设备树匹配链路不够规范。建议后续统一为同一个字符串。

---

## 4.3 驱动实现思路

AP3216C 驱动采用的是：

- **I2C 驱动框架**
- **misc 字符设备导出**

### 核心流程

#### 1）probe 阶段

驱动在 `probe()` 中主要完成：

- 为设备私有结构体分配内存
- 保存 `i2c_client`
- 初始化互斥锁
- 调用 `misc_register()` 注册字符设备

注册成功后，系统中会出现：

```bash
/dev/ap3216c
```

#### 2）open 阶段

当用户态第一次打开 `/dev/ap3216c` 时，驱动会：

- 先对 AP3216C 进行复位
- 等待器件稳定
- 再写入工作模式配置，使能 ALS 与 PS/IR

这一步相当于把“芯片初始化”放在第一次使用时完成。

#### 3）read 阶段

当用户态调用 `read()` 时，驱动会：

- 读取 AP3216C 相关寄存器
- 解析出 IR / ALS / PS
- 将三路结果打包成数组返回给用户态

### read 返回格式

驱动向用户态返回的是 3 个 16 位数据：

```c
short data[3];
```

对应关系为：

- `data[0] = ir`
- `data[1] = als`
- `data[2] = ps`

因此用户态只需要按这个顺序取值即可。

## 4.4 CLI 测试程序

项目中 AP3216C 已经配有最小化 CLI 验证程序：

- 文件：`apps/cli/i2c/ap3216c/ap3216cAPP.c`

CLI 测试程序的基本流程是：

1. `open("/dev/ap3216c", O_RDWR)`
2. 循环调用 `read()`
3. 分别取出 IR / ALS / PS
4. 打印到终端

这样做的意义是：

- 在接入 Qt 之前先确认驱动链路是否正常
- 将问题隔离到“驱动层”还是“Qt 应用层”
- 降低调试复杂度

---

## 4.5 Qt 封装与读取链路

Qt 侧通过 `Ap3216cDevice` 类对 `/dev/ap3216c` 做了简单封装，核心接口包括：

- `open()`
- `close()`
- `isReady()`
- `lastError()`
- `readData(Ap3216cData &data)`

其中：

```cpp
struct Ap3216cData
{
    unsigned short ir;
    unsigned short als;
    unsigned short ps;
};
```

Qt 页面读取流程为：

1. 应用启动时尝试打开 `/dev/ap3216c`
2. 若打开失败，则禁用 AP3216C 读取按钮
3. 用户点击 “Read AP3216C”
4. 调用 `m_ap3216c.readData(data)`
5. 更新界面标签：
   - `IR: ...`
   - `ALS: ...`
   - `PS: ...`

### 当前状态

当前 AP3216C 在 Qt 中已实现：

- 手动读取
- 数值显示
- 设备可用性检查
- 打开失败时按钮禁用

### 后续建议

AP3216C 后续可继续扩展为：

- 自动刷新（`QTimer`）
- 刷新周期可配置
- 亮度等级或接近状态判断
- 与其它传感器共同放入 `SensorPage`

# 5. ICM20608 模块说明

## 5.1 模块简介

ICM20608 是一颗六轴惯性测量传感器（IMU），一般可提供：

- 三轴加速度
- 三轴角速度
- 温度

在本项目中，Qt 界面已经按照以下字段进行显示：

- `Accel X / Y / Z`
- `Gyro X / Y / Z`
- `Temp`

这说明当前用户态接口已经整理成了适合应用直接使用的结构化数据，而不是原始寄存器字节流。

---

## 5.2 硬件连接与设备树

当前 DTS 中 ICM20608 节点位于 `&ecspi3` 下，典型写法如下：

```dts
&ecspi3 {
    fsl,spi-num-chipselects = <1>;
    cs-gpios = <&gpio1 20 GPIO_ACTIVE_LOW>;
    pinctrl-names = "default";
    pinctrl-0 = <&pinctrl_ecspi3>;
    status = "okay";

    spidev0: icm20608@0 {
        compatible = "alientek,icm20608";
        spi-max-frequency = <8000000>;
        reg = <0>;
    };
};
```

### 含义说明

- `&ecspi3`：ICM20608 连接在 ECSPI3 控制器上。
- `reg = <0>`：片选编号为 0。
- `spi-max-frequency = <8000000>`：SPI 最高速率为 8 MHz。
- `cs-gpios`：片选由指定 GPIO 控制。
- `compatible`：用于驱动匹配。

因此，从接口层面看，ICM20608 这条线属于：

**SPI 设备树 + 驱动匹配 + 字符设备用户态访问**。

---

## 5.3 驱动侧说明

从当前项目现状来看，ICM20608 最终目标链路应与 AP3216C 类似：

- 底层驱动完成 SPI 读写和寄存器解析
- 驱动导出 `/dev/icm20608`
- 用户态通过 `read()` 直接获取整理后的传感器数据

不过需要说明的是：

> 当前上传的压缩包中 `drivers/icm20608/icm20608.c` 内容与 ICM20608 模块不匹配，更像是历史文件或误放文件。因此，本文档中关于 ICM20608 驱动内部细节，建议以你当前工程实际运行版本为准，并在后续将仓库中的驱动文件与实际代码同步。

如果你的当前实际驱动已经可用，那么建议后续把 README 中这一节补充完整，包括：

- 寄存器初始化流程
- WHO_AM_I 校验
- 加速度/角速度原始值拼接方式
- 温度换算公式
- `/dev/icm20608` 注册过程
- `read()` 返回的数据结构

---

## 5.4 Qt 封装与读取链路

Qt 侧已经接入 `Icm20608Device`，并在界面中完成了单次读取与显示。

界面中读取成功后，会刷新：

- `Accel X / Y / Z`
- `Gyro X / Y / Z`
- `Temp`

从当前 Qt 代码的显示格式可以判断，用户态已经把 ICM20608 数据整理成如下逻辑结构：

```cpp
struct Icm20608Data
{
    float accelX;
    float accelY;
    float accelZ;

    float gyroX;
    float gyroY;
    float gyroZ;

    float temp;
};
```

Qt 页面读取流程可概括为：

1. 程序启动时尝试打开 `/dev/icm20608`
2. 如果打开失败，则禁用 “Read Icm20608” 按钮
3. 点击按钮后调用 `m_icm20608.readData(data)`
4. 使用格式化字符串将加速度、角速度和温度显示到页面标签中

### 当前状态

当前 ICM20608 在 Qt 中已实现：

- 手动读取
- 三轴加速度显示
- 三轴角速度显示
- 温度显示
- 打开失败时按钮禁用

### 后续建议

ICM20608 后续更适合扩展为：

- 定时自动刷新
- 采样频率配置
- 与 UI 显示频率分离
- 独立采集线程（高频场景）
- 后续姿态解算、滤波或曲线显示

# 7. 当前存在的问题与注意事项

## 7.1 AP3216C compatible 需统一

建议统一设备树与驱动中的 `compatible` 字符串，避免后续匹配隐患。

## 7.2 AP3216C 驱动中调试打印过多

驱动中存在类似：

- `ap3216c SYSTEMCONG=...`
- `ap3216c_read: IR=..., ALS=..., PS=...`

这类调试输出如果直接打到 LCD 控制台，可能会影响触摸屏 Qt 画面显示。建议后续：

- 调试完成后删除或注释
- 或改成 `pr_debug` / `dev_dbg`

## 7.3 ICM20608 驱动源码需与当前工程同步

当前仓库中的 `drivers/icm20608/icm20608.c` 与实际模块不匹配，建议尽快用当前可运行版本替换，避免后续 README 与工程脱节。
